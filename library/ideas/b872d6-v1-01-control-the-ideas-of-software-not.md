# Control the ideas of software, not its code

As AI generates large amounts of code, the valuable part of software work shifts from reading lines to deciding what the software should do. The author argues that a developer who controls the design, the features and the direction gets more done than one who checks every function. Reviewing thousands of generated lines a day is impractical, and LLMs write locally good code while struggling with big architectural choices. ==The leverage lies in the ideas, not the code==, so the developer should prompt the design, question how each part works, and evaluate whether the model is right.
